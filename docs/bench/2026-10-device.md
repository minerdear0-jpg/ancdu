## С root: `/data` напрямую и спайк memfd

**Не выполнено**: пользователь решил пропустить root-часть (root для Shell в Magisk не выдан).
Замер `/data` под root и проверка memfd через `/proc/<pid>/fd` переносятся в первую задачу плана 2 —
из домена самого приложения, что и так требовалось для окончательного решения (§5.3 спецификации).
Инструмент для спайка готов: `tools/memfd_probe.c` (цель `memfd_probe` в Android-сборке).

### memfd через su — попытка (2026-10-06)

```
$ adb shell /data/local/tmp/memfd_probe /data/local/tmp/libancdu_scan.so /sdcard
Permission denied
rc=3328 state=0 count=0 disk=0 ms=32
```

`su` из домена shell отклонён Magisk (root для Shell не выдан) — до memfd дело не дошло.
**Решение для плана 2:** первая задача проверяет memfd из домена приложения (Magisk спросит root у ancdu);
до получения результата основной путь root-режима — pipe-дамп (`--dump`), memfd — опционально.

**Обновление:** спайк выполнен из домена приложения и успешен (memfd=1) — см. «Приложение (2026-10)».

### Отмена root-скана

`ScanActivity` запущена для `/data` с su=true, «Назад» нажато через ~80 мс — возврат в `MainActivity`; процессов `libancdu_scan` нет сразу и через 3 с; процессов `su`, принадлежащих `dev.ancdu`, нет (два присутствующих `su` принадлежали Magisk и Material Files). Ручная попытка «/» + «Отмена» не успела: скан завершился за 129 мс.

### Сравнение с du под root

**Не измерено** (критерий ≥ 2× быстрее `du`): Magisk хранит запомненный отказ для Shell (`adb shell su` → Permission denied), `du` под root запустить нельзя. Для справки: ancdu root `/data` — 195 мс на 69 370 файлов.
